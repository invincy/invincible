## Interface and executor

Creator Studio's existing Video Studio has a Create an image panel inside Add assets.
The existing local AI page also includes the panel and its isolated project selector.
Both use `generate_image` registered in the existing Universal Agent API. Qwen emits
a candidate tool call; it cannot supply an executable graph. Manual generation
never asks Qwen. The existing Firebase task-bridge path remains separate; remote
image generation through that bridge was not enabled or deployed by this change.

The only tool arguments are a trimmed prompt (1–1,500 characters), `square`,
`portrait` or `landscape`, and an optional unsigned 32-bit seed. The graph is based
on the installed tested Indian-Fortress-SD15 workflow: the same FP16 SD 1.5 checkpoint,
built-in nodes, Euler, 20 steps, CFG 7, batch one, and server-generated output prefix.
Square is 512×512; portrait 384×640; landscape 640×384. All are multiples of 64 and
at or below the square pixel budget. All three presets passed real generation on this laptop; timings are recorded below.

Jobs expose queued, running, completed or failed. The executor checks the exact
ComfyUI prompt ID, SaveImage node and output prefix, then retrieves that output via
loopback HTTP. Completion requires PNG signature, chunk CRCs, dimensions, supported
encoding, complete decompression, pixel-filter validity, saved bytes and SHA-256.
Retrieval rechecks saved integrity. Bad bytes invalidate the job and disable downloads.

Job JSON and original PNGs live only below the authorized
`E:\Invincible\AgentWorkspace\image-generation\<owner-hash>` directory. Paths are
generated by the server; links and traversal are rejected. Request keys survive
restart in job metadata. Concurrent duplicates share one job; changed arguments
with a reused key fail. Interrupted jobs are marked failed on restart, never
blindly resubmitted. A workspace-wide exclusive worker lock prevents another
worker from taking over live GPU state. A stale PID lock is reclaimed only if that
process no longer exists; ambiguous state requires operator inspection.

The worker serializes its Qwen and image requests. It unloads image weights before
Qwen, unloads Qwen before images, and confirms image memory release afterward.
Failed cleanup blocks further GPU requests. Cancellation/timeout uses a targeted
ComfyUI interrupt, not a global interrupt. Independent clients of Ollama/ComfyUI
are outside this coordinator; existing queued foreign work is rejected as busy.

The panel decodes the preview and checks dimensions, downloads the verified PNG,
and attaches through the existing Video Studio uploadFiles → inspectMedia →
useMedia flow. Existing Firebase authentication, owner checks, media upload and
draft-saving behavior remain in place. Attach adds the asset to the current video
draft; Save retains the existing draft persistence semantics. Local AI test-project
attachments use an isolated owner-scoped project record with content identities.
No production account record was changed during verification.

## Local authentication and startup

The new worker binds to `127.0.0.1` only. All APIs require a fresh bearer pairing
token. Host and Origin checks reject untrusted websites; the optional app Origin
is restricted to an exact loopback origin or `https://invincy.github.io`.
The server configures the owner UID;
request bodies cannot select a principal or workspace. Creator and React clients
also require their current Firebase user to match that owner and stop on account
changes. This local pairing credential is separate from Firebase agent tokens.

Run the Invincible Image Studio shortcut as the normal laptop owner. It uses the
Windows-encrypted credential to launch the existing non-administrator worker.
`E:\Invincible\ImageGen\worker-config.json` supplies ownerUid, appOrigin and port
(8788); the configured owner must match the signed-in Firebase account.
In Creator's Add assets panel or Invincible AI with Local selected, choose
Connect this laptop, then confirm Connect Invincible in the local popup.
The handoff validates the exact popup source, origin, account and nonce; the
verified connection is remembered in this browser for the signed-in account.
Chrome may ask permission to connect locally on first use.
The private local pairing link remains available for the isolated local UI.
Keep ComfyUI running using its existing E: installation launcher.
The new worker does not install or start models, launch shells from tools, or
modify Windows permissions. The existing service on 8787 was not replaced.

The user explicitly authorized resetting only the existing worker login. The
password is strong, random, never printed, and stored as a Windows DPAPI-encrypted
credential at E:\Invincible\ImageGen\worker-login.dpapi for the current laptop
owner. The reusable launcher decrypts it locally and starts Node directly under
InvincibleAgent's existing standard login. No daily password entry or administrator
approval is needed. The restricted account's PowerShell execution policy remains
unchanged. The attempted scheduled task was removed because Windows denies this
account batch logon; no new logon right was granted. Folder ACLs and group
membership were preserved.

Use the Invincible Image Studio shortcut or local-ai/start-image-studio.cmd.
The shortcut starts or reuses ComfyUI and the restricted worker, then opens
Invincible AI's Images tab for the configured account. No router port,
public listener or remote tunnel is required. This connection operates on the
laptop running both services. No production account write was tested here.
GitHub Pages staging includes the public shared client and excludes local worker
and Firebase server source. The static publication does not deploy Functions.

## Remember this laptop

Successful pairing is saved for the exact loopback worker and Invincible UID in
the current browser profile. Another tab, a browser restart, or switching between
Creator and AI does not require a new pairing. A different signed-in account does
not inherit the connection. Existing valid tab credentials are migrated only after
session verification. Advanced settings includes Forget this laptop. A rejected
key is removed; a temporarily offline worker keeps the remembered connection and
offers Check connection instead of requesting another pairing.

The existing laptop-owner launcher protects its stable worker bearer with Windows
DPAPI in the ImageGen installation directory. It adopts the current key only after
verifying the worker owner and workspace. This preserves the current connection
without forcing a restart. The key is passed privately to the restricted worker at
startup and removed from its inherited environment after reading. Changing the
configured owner rotates the key. The separate Windows worker login is unchanged.
The launcher starts the existing ComfyUI installation silently when needed; GPU
model swapping remains the image worker's responsibility.

## Draft prompts and reuse creations

Use **Describe your idea** and **Generate prompt** on a paired laptop to draft
with local Qwen. Review the result in **Prompt**, then click **Generate** to
render. An in-flight draft never overwrites newer edits. The worker serializes
drafting with GPU work and releases Qwen after the draft. Manual prompts still
work without Qwen. Remote image generation can use manually entered prompts.

**Image history** saves completed PNGs, prompts and settings in this browser,
scoped to the signed-in account and current project or personal studio. Open a
creation to restore its preview and settings, then generate a new version.
Deleting a history entry removes its browser copy. Downloaded and attached
copies remain available. History starts with creations saved by this version.

On the paired laptop, **Reference image** accepts one JPEG or PNG up to 10 MB.
The browser previews a 512 × 512 center crop and sends that crop to the worker
when you click Generate. ComfyUI uses the same SD 1.5 checkpoint with a fixed
image-to-image workflow at 0.45 denoise. The reference is uploaded into
ComfyUI's temporary directory. Image history retains the finished PNG and
records that a reference was used. Reattach the original to reuse it later.
Mobile reference upload is pending. Qwen continues drafting from the written idea.

## Generate from a phone

Open Invincible Image Studio on the Windows laptop and leave it awake and online.
On the phone, sign in to the same Invincible account and open Invincible AI →
Images or Creator Studio → Image generator. Browsers without a remembered local
connection use the remote connection by default. A paired browser can switch
using **Use my laptop remotely**. Check connection refreshes laptop availability
after opening Image Studio. No phone pairing code is needed.

The outbound image connector uses the existing Windows-encrypted Firebase agent
credential. It checks that the agent and loopback image workspace have the same
owner before claiming jobs. The existing text connector remains independent.
Only the approved prompt, frame and optional seed reach the same local
generate_image worker. It still controls the fixed workflow, PNG verification,
workspace writes and GPU cleanup. The worker and ComfyUI remain on loopback.

The Firebase callable scopes the queue and downloads to the signed-in owner.
Agent actions require the indexed, unexpired agent credential and job updates
require its active lease. Firestore receives the prompt while the job is active
and retains up to four verified PNGs per account in a server-only collection.
New images replace the oldest relay copy. Download an image or attach it through
Creator's existing upload path to retain it independently of that limit.
Only one remote generation per account can be active. A laptop that sleeps or
loses connectivity can leave a job waiting until its deadline expires. If the
existing Firebase agent credential expires or is revoked, renew it through the
same Invincible local AI connection and reopen Image Studio.

The relay tests exercise ownership, idempotency, leases, offline handling and
PNG validation. The mobile-size browser fixture checks preview, download, the
attachment callback and failure with loopback blocked.
